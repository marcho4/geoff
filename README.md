# Geoff

Geoff каждое утро читает вашу Яндекс-почту и чаты из папки Telegram, просит нейросеть составить сводку и присылает её вам в Telegram от вашего бота.

Все команды ниже выполняются **из папки проекта** (той, где лежит этот README), если не сказано другое. Пути к файлам указаны относительно неё.

Что лежит в папке:

| Файл | Где запускается | Зачем |
|---|---|---|
| `tdata_to_session.py` | ноутбук | достаёт сессию Telegram из Telegram Desktop |
| `yandex_email_parser.py` | сервер | выгружает письма за последние `HOURS_BACK` часов в `out/yandex_emails.json` |
| `telegram_messages_parser.py` | сервер | выгружает сообщения из папки `TG_FOLDER` в `out/telegram_export.json` |
| `send_tg.py` | сервер | один раз печатает ваш `TG_CHAT_ID` |
| `send_summary.py` | сервер | отправляет сводку в Telegram (длинную режет на части) |
| `run.sh` | сервер, по cron | запускает всё по очереди: выгрузка → сводка в `results/summary_ДАТА.md` → отправка |
| `requirements.txt` | сервер | библиотеки Python |
| `.env.example` | — | шаблон файла с ключами |

# 1. Настройка сервера

Заходим на сайт любого провайдера, я рекомендую https://vdsina.com. Оплачиваем там зарубежной картой или криптой.
Тариф по 0.07$ в день. Система — Ubuntu.

Если нет возможности купить зарубежный хостинг, то берем русский сервер и везде используем прокси.

Для использования прокси добавляем в терминал перед каждой командой `HTTP_PROXY=<ваша прокси>`. Или один раз вводим `export HTTP_PROXY=<ваша прокси>`.

Затем получаем IP адрес, логин и пароль. Для подключения к серверу выполняем команду
`ssh <user>@<IP>` на вашем ноуте без прокси. Вас спросят пароль, вставляете и жмете enter. Вы окажетесь на сервере. К серверу будет доступ только у того, кто знает пароль. На сервер уже нужен прокси, если сервер в России.

## 1.1 Файлы проекта и Python

Кладем папку проекта на сервер в домашнюю папку (`~/geoff`). Либо через git:

```sh
git clone <ссылка на репозиторий> ~/geoff
```

либо копируем с ноутбука:

```sh
scp -r <папка geoff на ноутбуке> <user>@<IP>:~/geoff
```

Дальше на сервере заходим в папку и ставим библиотеки в отдельное окружение (venv — папка с Python и библиотеками только для этого проекта):

```sh
cd ~/geoff
sudo apt update && sudo apt install -y python3 python3-venv
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
chmod +x run.sh
mkdir -p out results
```

Создаем файл с ключами из шаблона и закрываем его от других пользователей сервера:

```sh
cp .env.example .env
chmod 600 .env
```

Редактировать его будем так: `nano .env`, затем `Ctrl+O`, `Enter` (сохранить), `Ctrl+X` (выйти). Значения пишем без пробелов вокруг `=` и без кавычек.

# 2. Настройка окружения

Для этого понадобится агент, ключи приложения телеграма, сессия вашего аккаунта телеграмма, папка в телеграмме с вашими чатами для саммаризации, токен от почты. Всё это будем складывать в файл `.env`. Теперь подробнее про каждый из этих пунктов.

Перед каждой ручной проверкой ниже подгружаем `.env` в терминал:

```sh
set -a && . ./.env && set +a
```

## 2.1 Агент

Я использую claude code, но можно и других по типу codex или opencode.
Выбирайте тот, который вам удобнее. Если это не Claude, то надо подправить `run.sh` в месте вызова агента (`claude -p ...`). Нейросеть с этим справится, просите её.
Команды для скачивания на сервер:

```sh
curl -fsSL https://claude.ai/install.sh | bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
curl -fsSL https://opencode.ai/v2/install | bash
```

После установки один раз запускаем агента (`claude`) и логинимся по подсказкам. Если у вас подписка, не задавайте `ANTHROPIC_API_KEY`, иначе сводки пойдут через платный API.

Запоминаем, где лежит агент, это понадобится для cron:

```sh
which claude
```

Обычно это `/root/.local/bin/claude`.

## 2.2 Сессия телеграм

Скачиваем с desktop.telegram.org приложение Telegram Desktop, логинимся и выполняем скрипт. Затем у вас скачается файл с сессией телеграмма и надо этот файл положить в папку к Geoff'у.

Войти в телеграм прямо со скрипта по коду не получится: Telegram не присылает коды сторонним клиентам. Поэтому логинимся в официальное приложение и берем сессию оттуда.

Важно:
- Качать именно с desktop.telegram.org. Версия из App Store или Microsoft Store не подойдет, у нее нет папки `tdata`.
- После входа полностью закрываем приложение (на Mac `Cmd+Q`).
- Если в Desktop стоит локальный код-пароль (Настройки → Конфиденциальность → Код-пароль), на время конвертации его надо выключить.

На ноутбуке кладем скрипт `tdata_to_session.py` из папки проекта в любую папку и выполняем там:

```sh
# Mac / Linux
python3 -m venv .venv && source .venv/bin/activate
pip install TGConvertor
python tdata_to_session.py
```

```powershell
# Windows (PowerShell)
python -m venv .venv; .\.venv\Scripts\Activate.ps1
pip install TGConvertor
python tdata_to_session.py
```

Если всё хорошо, скрипт напишет `ok, dc: <число>`, а рядом появится файл `tg_session.session`. Если пишет `tdata not found` — стоит Telegram из магазина, а не Desktop. Переносим файл на сервер в папку проекта:

```sh
scp tg_session.session <user>@<IP>:~/geoff/
```

После этого удаляем `tg_session.session` с ноутбука: одна сессия не должна работать с двух мест.

## 2.3 Папка телеграма

Создаем папку в телеграмме с чатами и добавляем туда всё, что хотите ежедневно читать Geoff'ом.
Название этой папки сохраняем в `.env` строчкой `TG_FOLDER=<Название вашей папки>`. Регистр должен совпадать.

## 2.4 Токен от почты

Заходите на id.yandex.ru, переходите в Безопасность -> Пароли приложений -> Почта и там получаете пароль.
В `.env` дописываете ваш логин от почты и полученный пароль.
Без двухфакторной аутентификации пункта «Пароли приложений» не будет.
Нужно включить IMAP: mail.yandex.ru → Все настройки → Почтовые программы → галочка «С сервера imap.yandex.ru по протоколу IMAP». Без этого будет AUTHENTICATIONFAILED.
Логин пишется полным адресом, с @. Для ВШЭ это обычно @edu.hse.ru.

```txt
YANDEX_LOGIN=<ваш логин>@yandex.ru
YANDEX_APP_PASSWORD=<ваш пароль>
MAIL_OUTPUT=./out/yandex_emails.json
OUTPUT_DIR=./out
HOURS_BACK=24
```

Проверяем:

```sh
set -a && . ./.env && set +a && .venv/bin/python3 yandex_email_parser.py
```

Успех: `Saved N messages to ./out/yandex_emails.json` (N может быть 0).

## 2.5 Ключи для телеграма

Нужны две пары ключей: ключи приложения, чтобы читать чаты, и токен бота, чтобы получать сводку.

### Ключи приложения

Заходим на my.telegram.org и вводим номер. Код придет в приложение Telegram, не по SMS. Переходим в API development tools и заполняем:
- App title: `geoff`
- Short name: `geoff`
- Platform: Desktop
- остальное оставляем пустым.

Жмем Create. Появятся `App api_id` (число) и `App api_hash` (строка). Дописываем в `.env`:

```txt
TG_API_ID=<api_id>
TG_API_HASH=<api_hash>
TG_OUTPUT=./out/telegram_export.json
```

Если пишет `Too many attempts`, это не бан: ждем час и не жмем повторно, иначе лимит продлевается. Если при создании `ERROR`, пробуем другой браузер или выключаем VPN.

Проверяем (файл `tg_session.session` уже должен лежать в папке проекта):

```sh
set -a && . ./.env && set +a && .venv/bin/python3 telegram_messages_parser.py
```

Успех: `Saved N messages from M chats to ./out/telegram_export.json`. Скрипт ничего не должен спрашивать. Если спросил номер телефона — жмем `Ctrl+C`: сессия не подхватилась, проверьте, что файл называется ровно `tg_session.session` и лежит рядом со скриптом. `Folder '...' not found` — поправьте `TG_FOLDER`.

### Бот для сводки

В Telegram открываем @BotFather и отправляем `/newbot`. Имя любое, username должен заканчиваться на `bot`. BotFather пришлет токен. Дописываем в `.env`:

```txt
TG_BOT_TOKEN=<токен>
```

Находим своего бота в поиске и пишем ему «привет». Потом узнаем chat_id:

```sh
set -a && . ./.env && set +a && .venv/bin/python3 send_tg.py
```

Напечатается число — это ваш chat_id. Если `list index out of range`, значит вы еще не написали боту. Дописываем в `.env`:

```txt
TG_CHAT_ID=<chat_id>
```

Проверяем отправку:

```sh
printf '# Тест\n\n**Geoff подключен**\n' > results/test.md
set -a && . ./.env && set +a && .venv/bin/python3 send_summary.py results/test.md
rm results/test.md
```

Бот должен прислать сообщение.

# 3. Активация Geoff'а

## 3.1 Пробный запуск

Сначала запускаем всё целиком так, как это будет делать cron (без вашего `PATH` и профиля). Вместо `/root/.local/bin` подставьте папку из `which claude`:

```sh
env -i PATH=/root/.local/bin:/usr/local/bin:/usr/bin:/bin HOME=$HOME ./run.sh
```

Через пару минут бот пришлет настоящую сводку, а в `results/` появится `summary_<сегодняшняя дата>.md`.

- Если сводка за сегодня уже есть, `run.sh` её не пересоздает, а только отправляет повторно. Для чистого прогона удалите `results/summary_<дата>.md`.
- `claude: command not found` — неправильный путь к агенту в `PATH`.
- `Claude не записал сводку` — агент не получил права на запись или не залогинен; запустите `claude` руками и проверьте.

Текст промпта для сводки лежит прямо в `run.sh` — меняйте его под себя.

## 3.2 Расписание

cron — встроенный в сервер будильник, который запускает команду по расписанию. Ставим запуск каждый день в 8:00 (команду выполняем из папки проекта, `$(pwd)` подставит полный путь к ней):

```sh
(echo "PATH=/root/.local/bin:/usr/local/bin:/usr/bin:/bin"; echo "0 8 * * * $(pwd)/run.sh >> $(pwd)/cron.log 2>&1") | crontab -
crontab -l
```

Строка `PATH` обязательна, без неё cron не найдет агента. Время считается по часовому поясу сервера, посмотреть его можно командой `timedatectl`. Если там не Москва, поставьте Москву:

```sh
sudo timedatectl set-timezone Europe/Moscow
```

Если вы перенесли папку проекта в другое место, команду с `crontab` нужно выполнить заново: в cron записан полный путь.

## 3.3 Если сводка не пришла

Смотрим лог:

```sh
tail -30 cron.log
```

- `No module named telethon` — не создан `.venv` или в нём не установлены библиотеки (шаг 1.1).
- `AUTHENTICATIONFAILED` — пароль приложения или IMAP (шаг 2.4).
- `No such file or directory: .../run.sh` — папку проекта перенесли, перезапишите crontab (шаг 3.2).

Выключить Geoff'а: `crontab -r`.

# Важные замечания

Файлы `.env` и `tg_session.session` - секреты. Их нельзя давать нейросети и сторонним людям. Если случайно показали токен — перевыпустите его.

В `out/` и `results/` лежат ваши письма, переписки и сводки. Их тоже не стоит никуда выкладывать.
